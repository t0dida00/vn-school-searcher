# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

FinUnies is a search app for Finnish universities, UAS and vocational schools (live at finunies.vercel.app, deployed on Vercel). Since adding Vietnam it covers several countries: on `/vn/...` the same app is branded VieUnies. The repo directory and some leftovers (`public/vn.json`, `public/dummy-list.geojson`, Vietnamese comments and UI strings such as tooltips) come from an earlier Vietnamese-school version. The current data is Finnish.

Stack: Next.js 15 App Router + React 19, TypeScript, MongoDB Atlas, Mapbox GL JS, Zustand, Tailwind v4 + shadcn/ui (new-york style), and SCSS modules for some components.

## Commands

```bash
npm run dev     # next dev --turbopack
npm run build
npm run start
npm run lint    # next lint (ESLint 9, next/core-web-vitals + next/typescript)
npm run export:map  # rewrite app/map/schools/<country>.json from MongoDB; run (and commit) after changing school data
```

There is no test suite.

## Environment (`.env.local`)

- `MONGO_URI`: required. `app/lib/mongodb.ts` throws at import time if it is missing, so the build fails too.
- `NEXT_PUBLIC_MAPBOX_ACCESS_TOKEN`: Mapbox token.
- `NEXT_PUBLIC_MAP_MIN_ZOOM/MAX_ZOOM`: zoom limits (defaults in `app/map/mapboxConfig.ts`). The initial view is not configurable: `app/map/viewport.ts` fits the country's `bounds` (from `app/map/countryMaps.ts`) on load (padded clear of the search panel), then sets min zoom and max bounds to exactly that fitted view, so the country can't be zoomed out past or panned off screen. It re-fits on resize while the user is at the overview zoom. `NEXT_PUBLIC_MAP_LONGITUDE/LATITUDE/ZOOM` are no longer read.
- `NEXT_PUBLIC_MAP_HIGHLIGHT_COUNTRY`: no longer read. The country comes from the URL (see `app/map/countryMaps.ts`).
- `NEXT_INTERNAL_BASE_URL`: no longer read. `/[country]/map` reads MongoDB directly.

## Architecture

**Countries.** Every page lives under `/<country>/...` (`app/[country]/`). The countries are listed in `app/lib/countries.ts`. Each entry has the code, name, adjective, MongoDB collection, brand (`FinUnies`/`VieUnies`, used in titles and copy), `hasMap`, ranking source and hero settings (rotating words, background, text-shadow). Today they are `fi` (`fin_universities`, 38 schools) and `vn` (`vn_universities`, 268 schools: the MOET-style list from Vietnamese Wikipedia plus uniRank, with member schools of the national and regional universities as their own entries linked by `properties.memberOf`, military and police academies marked by `properties.category`, and branch campuses in `campuses`. Only the uniRank top 20 have hand-written overviews; the rest have generated ones, and none have tuition, scholarship or contact data). Client code reads the current entry with `useCountryConfig()`. Each country also needs its own `public/filter-options/<code>.json`. The header shows the site-wide Unies mark (`UniesMark`, linking to `/`), not a country logo. The hero, sub-footer, `RankTag` and page titles read the entry, so don't hard-code "FinUnies" or "Finland" in them. `app/[country]/layout.tsx` sets `dynamicParams = false`, so unknown codes return a 404. Build in-app links with `useCountryPath()` (client) or `countryPath()` (server), never as bare `/map`. `useDataStore.country` records which country `data` belongs to, and `/university-list` refetches when it doesn't match the URL. A country with `hasMap: true` needs an entry in `app/map/countryMaps.ts` (both `fi` and `vn` have one). Without a map, `/<code>/map` returns 404 and the map links (header, hero, the list's "Map view" button and the school page's "View on map") are hidden. `/<code>` on its own redirects to `/<code>/university-list`. `hero.flag` draws the list hero as the country's flag: `cross` (Finland's Nordic cross) or `star` (Vietnam's star, centred behind the headline at `opacity` so the white text stays readable). `app/components/CountryFlag.tsx` draws the same flags small, and exports the star shape the hero uses.

**Landing page.** `/` (`app/page.tsx`, static with `revalidate = 3600`, outside `[country]`) is the site's front page under the overall brand, Unies. Its pieces live in `app/components/landing/`: its own header (`SiteHeader`, with `UniesMark`: the cap-and-book cropped out of `/logo.png` with "Unies" stacked below it, the site-wide logo also used by the country header and the footer), headings in Zilla Slab (`app/fonts.ts`, loaded as `--font-slab` in the root layout), and `FlagBook`, the logo's open book printed with every country's flag, whose pages open on load before the cap drops onto the spine. Below the hero, two rows of school logos drift past (`MarqueeRow` from `app/components/LogoMarquee.tsx`, shared with the country hero), then a short feature list, the chooser, a card per entry in `COUNTRIES` (flag, school count read from MongoDB through `getSchools()`, links to the list and map) beside the globe (`CountriesLayout`), and the site-wide questions and answers (`GeneralQnA`, `/#faq`, which the country list pages link to from their sub-footer instead of keeping their own). Its copy names no country and gives no country count, so adding one to `COUNTRIES` needs no edits there. The country pages' header has `CountrySwitcher` (`app/components/CountrySwitcher.tsx`, a popover next to the logo), which switches country while keeping the section (the map stays the map when the other country has one; everything else goes to its list) and links to `/`. Below 360px it shows only the flag.

**Data source.** The list API is `app/api/universities/route.ts`, and `app/api/universities/[id]/route.ts` returns one school's full document. `?country=<code>` picks that country's collection (it defaults to `fi`, and unknown codes return 404). It returns every document in that collection, with CORS set to `*`. Each document is already a GeoJSON `Feature` (`{ _id, type, geometry: Point, properties: { name, city, type, fieldOptions, logo, overview, tuition, scholarship, website, ... } }`). The client uses these documents directly as Mapbox features, with no transformation. `properties.fieldOptions` can be an array or a JSON-encoded string, so always read it through `app/utils/stringToArray.ts`. `properties.ranking` is the uniRank 2026 national rank as a string (`""` for TAMK, National Defence University and Police University College, which uniRank doesn't list). Read it through `rankOf()`/`byRanking()` in `app/utils/ranking.ts`, and show it with `app/components/RankTag.tsx`.

**Routing.** `next.config.ts` serves the landing page at `/` and redirects the old `/countries` there (permanent, 308). The old `/school-list`, `/university-list`, `/map` and `/school/:id` URLs, and `/<country>/school-list`, redirect permanently (308) to their `/fi/` or `/<country>/university-list` versions. `app/home/` is a placeholder. The two real views are:

- `/[country]/university-list` (`app/[country]/university-list/page.tsx`, client component): the list view. It calls `fetchData()` on the client and filters **client-side** by city, field and type. The options for those filters come from `public/filter-options/<country>.json`, and the values are lowercased for comparison. Text search and filters run together through a single `matches()` predicate, with `useDeferredValue` keeping typing responsive. Results scroll in pages of 10 via `react-intersection-observer`, and the page count resets whenever a filter changes. Cards live in `app/[country]/university-list/components/SchoolCard.tsx`.
- `/[country]/map` (`app/[country]/map/page.tsx`, fully static): makes no database or API call for the map. `app/HOC/MapWrapper.tsx` loads the country's slim school GeoJSON (`COUNTRY_MAPS[country].loadSchools()`, which imports `app/map/schools/<country>.json`) into `useMapDataStore`, and loads `app/components/Map.tsx` dynamically with `ssr: false`, because mapbox-gl needs `window`. The slim files hold only what pins, clusters and the map search need (id, name, code, logo, city, type, ranking, fieldOptions, and campus name/city/coordinates). They're generated by `npm run export:map` (`scripts/export-map-schools.mjs`), so after changing school data in MongoDB, rerun it and commit the files, or the map shows stale pins. When a school's dialog or drawer opens, `useSchoolDetails()` (`app/components/SchoolDetails/useSchoolDetails.ts`) fetches its full document from `/api/universities/<id>?country=<code>` (cached in memory for the session) and shows a skeleton until it arrives. Schools that already carry their full document, such as the list view's, skip the request.
- `/[country]/school/[id]` (`app/[country]/school/[id]/page.tsx`, SSG with `revalidate = 86400`, prerendered for every country): one page per school, keyed by the `properties.id` slug (`schoolId()` in `app/utils/schoolId.ts`). It reads MongoDB directly through `app/lib/schools.ts` (not over HTTP), so it prerenders during `next build`. It reuses the `SchoolDetailContent` pieces and links to `/<country>/map?school=<id>`, which `Map.tsx` opens on load. `app/sitemap.ts` lists these pages.

**State (Zustand, `app/zustand/`).**

- `useDataStore` holds the list view's full documents: `data` (all schools), `loading`, `error` and `fetchData`. `data`, `country` and `fetchedAt` persist to localStorage (`finunies-schools`, with `skipHydration`). `fetchData(country)` rehydrates first and skips the request while the cache is under 7 days old and belongs to that country. `{ force: true }` bypasses it. The data changes about twice a year: **after updating MongoDB, bump `SCHOOL_DATA_VERSION`** in `useDataStore.ts` to drop every visitor's cache. On the server, `/api/universities` and `/api/universities/<id>` send `s-maxage=86400` and the school pages revalidate daily.
- `useMapDataStore` holds the map's slim GeoJSON (`data`, `load(country)`) and `filteredData` (`null` means no search, so use `data`), which `MapSearch` writes and resets to `null` on unmount. `/university-list` filters locally and keeps its filters in the URL query (`q`, `city`, `field`, `type`).
- `usePointStore` holds `points` (all features visible in the current map bounds), `selectedPoint` and `isOpen` (the detail dialog or drawer).
- `useSavedStore` holds the shortlist (saved school ids), persisted to localStorage with `skipHydration`. Read it via `useSavedIds()`, which rehydrates after mount so server HTML matches. `SaveButton` toggles it. `/university-list` filters to saved schools with `?saved=1`.
- Imperative map code reads and writes these stores through `useStore.getState()`, not hooks.

**Map layer (`app/map/`).**

- `countryMaps.ts` holds each country's map pieces: `bounds`, an outline loaded on demand (`finland.json`, a simplified geoBoundaries/OSM outline under ODbL; `vietnam.json`, geoBoundaries gbOpen VNM ADM0 under CC BY 4.0, mainland plus coastal islands only), the cluster flag (drawn on a canvas, plus a halo colour for the count) and the loader art used by `MapLoading.tsx`.
- `layerConfig.ts` adds the country layers from that outline: an opaque `outside-country` mask (the world with the country as holes) covers the whole basemap, labels included, and a sand `country-silhouette` fades out between zoom 6 and 8 so streets appear when zoomed in. The map uses a flat `mercator` projection so the outline doesn't bend. The file also adds the clustered `universities` GeoJSON source, which has only the `clusters`, `cluster-flag` and `cluster-count` layers. Single schools are not a layer.
- `activeMap.ts` holds the country map on screen (no mapbox-gl import, so server-rendered details can use it). In the details' Campuses list, each row flies that map to the campus (`showOnMap()`, which also closes the dialog or drawer), or, with no map on screen, links to `/<country>/map?school=<id>&campus=<slug>`, which `Map.tsx` opens like a click on that campus's pin.
- `markers.ts` draws each unclustered school as an HTML logo marker, because circle layers can't show remote logos. `syncSchoolMarkers` runs on every `render` and adds or removes markers to match `querySourceFeatures`. Markers are keyed by `properties.id`. `selectSchool()` is the single entry point for opening a school: it sets `selectedPoint` and `isOpen`, then flies to the school. Marker CSS lives in `markers.module.scss`. Never give `.marker` a `position`, because that overrides `.mapboxgl-marker`'s absolute positioning.
- `events.ts` wires up map events: it recomputes visible points on move and zoom, syncs markers, expands a cluster on click, and toggles marker selected and highlight classes when `usePointStore` changes.
- `Map.tsx` creates the map once and then calls `setData` on the existing `universities` source whenever `filteredData` or `data` changes. It does not recreate layers.

**Map search (`app/components/MapSearch.tsx`).** A floating panel with instant search and type pills (only for the types in the data, and hidden when there's just one, as in Vietnam), both using `matchSchool()` from `app/utils/matchSchool.ts`, which `/university-list` shares. With no query, the panel lists the schools in view. With a query, it writes `filteredData` and fits the map to the matches, padded around the panel. It supports arrow, Enter and Escape keys, and hovering a result highlights its marker.

**Responsive split.** The breakpoint is `window.innerWidth >= 576` (`min-[576px]:` in Tailwind). Desktop opens details in `SchoolDetailDialog` and keeps the result list open. Mobile uses `SchoolDrawer` (vaul) and only expands the list while searching. Both detail views are thin wrappers: their content (header, body and the website and directions actions) lives in `app/components/SchoolDetails/SchoolDetailContent.tsx`, so change it there.

**Campuses.** `properties.campuses` (optional) lists a school's *other* teaching campuses as `{ name, city, address, coordinates: [lon, lat], sourceUrl }`. The school's own `geometry` and `city` are the main campus. Read campuses only through `app/utils/campuses.ts`:
- `campusesOf()` reads the list safely.
- `toMapFeatures()` expands schools into one map feature per campus. Campus feature ids are `<school id>~<campus slug>` with `parentId`.
- `parentIdOf()` maps any feature back to its school.

On the country maps, campus pins are smaller logo markers (`.campus` in `markers.module.scss`). Clicking one opens the school as seen from that campus: `campusView()` swaps in the campus's location, city and address, shows the campus name under the title, marks it "this campus" in the Campuses list, and keeps `mainCity` for the main-campus row. `updateVisiblePoints` lists each school once, and `matchSchool()` matches campus cities and names. The details show a Campuses section, and `SchoolCard` shows "+N campuses".

**Globe (`/countries`).** `app/countries/CountriesLayout.tsx` places the country cards on the left (60%) and the globe on the right (40%) from `lg` up. Its "Expand map" button spans the globe across the row and moves the cards below it in two columns. `GlobeMap` resizes itself with a `ResizeObserver`. Below `lg`, the globe stacks above the cards. `app/countries/page.tsx` passes slim school data to `app/components/GlobeMap.tsx` (loaded client-only through `GlobeMapLoader.tsx`). It uses mapbox-gl `projection: "globe"`, light style and fog:
- **Sources:** one clustered source per country (`schools-<code>`), whose clusters use `addFlagClusterLayers(..., suffix, true)` from `layerConfig.ts`. On the globe, badges shrink when zoomed out and get a dark ring.
- **Logo pins:** unclustered schools use the same logo markers as the country maps (`createLogoMarkerElement()` in `markers.ts`). Clicking one opens a popup linking to `/<code>/school/<id>` and the country map.
- **Highlight:** each supported country is filled with its hero colour (outline from `COUNTRY_MAPS`, with a glow line), and clicking the country zooms to it.

**Policy pages.** `app/(legal)/` holds `/privacy` and `/disclaimer` (shared `LegalPage` shell), which are linked from `Footer` together with a contact link. `app/components/Footer.tsx` is the one site-wide footer (the Unies mark, every country, the Q&A, sources, and a bottom row with © and the policy and contact links), used by the landing page, every country page, the policy pages and `ErrorScreen`; the map uses `<Footer compact />`, just the bottom row, so it keeps the screen. Above the bottom row, the full footer has a strip where `RobotCat` (`app/components/RobotCat.tsx`, styles in `robotCat.module.scss`) lives: an SVG robot cat in the Unies mortarboard that walks along the ground line toward the pointer's x position (or a tap), blinks, swishes its tail, follows the pointer with its eyes, and hops, waves and sends a heart when clicked. A frame loop moves it and writes the transform directly; it starts at the left end (pages float buttons over the bottom-right), pauses while off screen (IntersectionObserver) and stays still under reduced motion. On `/university-list`, scrolling to the footer loads more schools first, so the footer (and the cat) only stays in view once the list is fully loaded. The privacy policy describes what the code really does: no cookies, analytics or accounts; localStorage for the shortlist and cached data; Vercel, Mapbox and remote logos as third parties. **Update it whenever any of that changes.** The Q&A keeps only short answers that link to these pages. `CONTACT_EMAIL` lives in `app/lib/contact.ts`, a plain module, so server components can import it.

**Error pages.** `app/not-found.tsx` renders `app/components/NotFoundScreen.tsx`. It takes the country from the first URL segment, because unmatched URLs reach the root not-found without `[country]` params. It picks a theme from `THEMES`: Finland gets a night sky with aurora, and Vietnam gets a dusk sky with lanterns. Any other country, including unknown codes, gets the neutral `GENERIC` theme. `LostStudentArt` draws the matching scene (`fi`: pines, Finnish flag, reindeer; `vn`: palms, Vietnamese flag, water buffalo; `generic`: trees and a desk globe). Its buttons link to that country's pages, and the map button only appears when the country has a map. `global-error.tsx` reads the brand from the URL after mount.

**Reports.** The end of a school's details (`SchoolDetailBody`, so the dialog, drawer and school page) has "Report a problem" (`app/components/SchoolDetails/ReportProblem.tsx`): it opens in place with the reasons in `app/lib/reports.ts`, an optional note and, from a campus pin, the campus, posts to `/api/reports`, then shows a thank-you dialog. The route checks the country, school and reason, caps the note at 1000 characters, skips identical repeats within 10 minutes, and stores `{ country, schoolId, schoolName, reason, note, campus, status: "open", createdAt }` in `schoolAPI.reports`, with nothing about the sender. The privacy policy describes this; update it if the stored fields change.

**Icons.** `app/favicon.ico` (48px), `app/icon.png` (512px) and `app/apple-icon.png` (180px) are the Unies cap-and-book without text; Next.js serves them from the file names, so the root metadata has no `icons` entry.

**UI components.** shadcn primitives live in the root `components/ui/` and are imported via the `@/*` alias, which maps to the repo root. App-specific components live in `app/components/`, and their styles are in `app/components/styles/*.module.scss`. Use `cn()` from `lib/utils.ts` to merge class names. Text inputs, selects and textareas must be at least 16px so iOS doesn't zoom in on focus: don't give them `text-sm`/`text-xs` (an unlayered rule in `globals.css` enforces this as a safety net). Check layouts down to 280px wide (Galaxy Fold) and on landscape phones (about 740×360).
